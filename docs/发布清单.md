# EasyShare 模板发布清单

此清单供模板维护者使用。当前交付仅包含本地项目，没有创建远程仓库、推送代码或发布演示站。

## 发布前本地检查

- [ ] 修改默认配置时保留通用示例，不写入个人邮箱、统计标识符或文章。
- [ ] 运行 `npm ci`、`npm run check` 和 `npm run build`。
- [ ] 使用 `npm start` 检查首页、文章、搜索、归档、图片和主题切换。
- [ ] 确认 `.gitignore` 排除 `node_modules/`、`.next/`、`out/`、环境文件和缓存。
- [ ] 保留 MIT 版权声明及第三方署名。

## 创建并发布模板仓库

1. 在 GitHub 创建名为 **EasyShare** 的公开空仓库，不预先生成 README、LICENSE 或 `.gitignore`。
2. 在本项目目录运行以下命令，将 `YOUR_USERNAME` 替换为实际账号：

   ```bash
   git init -b main
   git add .
   git commit -m "Initialize EasyShare template"
   git remote add origin https://github.com/YOUR_USERNAME/EasyShare.git
   git push -u origin main
   ```

3. 在 **Settings → General** 勾选 **Template repository**，确认仓库主页出现 **Use this template**。
4. 核对 README 和页脚中的项目品牌链接；当前页脚指向原作者的 `odd256/EasyShare`。若模板发布位置不同，更新页脚项目地址。

发布后的模板默认保留 localhost，供用户先本地预览。因此，模板仓库自身不配置演示站时，主分支部署会因为未启用 Pages 或未修改公开地址而失败；PR 检查仍可正常执行。用户应按 README 配置后部署。

如后续需要演示站，建议从模板创建独立演示仓库，修改该仓库配置并部署，让模板保持通用默认值。

## 验证模板创建体验

- [ ] 使用 **Use this template** 创建一个测试仓库，默认分支为 `main`。
- [ ] 克隆测试仓库；执行 `npm ci`，修改 `config/site.ts` 的作者、标题与实际 Pages 地址。
- [ ] 替换首页与示例文章，运行 `npm run check` 和 `npm run preview`。
- [ ] 在测试仓库 **Settings → Pages** 中将来源设为 **GitHub Actions**。
- [ ] 推送 `main`，确认 Actions 的 build、deploy 成功。
- [ ] 从部署地址直接打开并刷新嵌套文章，检查图片、搜索跳转、标签和正文链接。
- [ ] 分别核对普通仓库子路径与用户站点地址；有自定义域名时再检查 DNS、HTTPS 和域名切换后的路径。

GitHub 仓库设置和线上部署需要在发布阶段实际验证，本地构建不能替代这些检查。
